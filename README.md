# Баланс команд

Мобильное веб-приложение (PWA) для распределения игроков в футбол на 2 или 3 команды
с примерно равной суммой скилов. Без сборки, без зависимостей, без бэкенда.

## Главное про модель

Вратарём может встать **любой**, и в поле игроки тоже меняются позициями.
Поэтому:

- у каждого игрока заполняются **все 8 скилов** — 7 полевых и 1 вратарский;
- колонка «Позиция» не нужна и не используется;
- у игрока две оценки: **«в поле»** и **«в воротах»**;
- в результате для каждой команды подписан сильнейший вратарь — кто может встать в рамку.

## Скилы (шкала 1–10, можно половинки)

**Поле (7):** Скорость, Удар, Пас, Дриблинг, Защита, Физика, Позиционирование.
**Ворота (1):** Реакция — единственный скил, который идёт в вратарскую оценку.

«В поле» и «в воротах» — простое среднее по своей группе. Пустые ячейки подставляются
средними по составу, так что недозаполненная таблица не ломает баланс.
Если в таблице числа из FIFA (0–99), они автоматически делятся на 10.

## Что умеет

- Состав из **Google Таблицы** по ссылке, вставкой CSV или вручную.
- Делит на **2 или 3 команды**: выравнивает сумму полевых оценок, а при включённой
  галочке — и сумму вратарских.
- Показывает суммы, средние по команде, вратарскую сумму и вратаря каждой команды.
- Кнопка «Ещё вариант» пересобирает состав, «Поделиться» отдаёт текст в мессенджер.
- **Дата игры** выбирается сама (ближайшая), но её можно поменять вручную — список дат берётся
  из шапки листа явки.
- **История игр**: «Сохранить игру» пишет дату, составы и счёт в лист «История» Google Таблицы.
- **Статистика** по истории: посещаемость и очки игроков, сыгранность пар, попадание баланса
  в результат.
- **Адреса уже вписаны** в приложение: состав, явка, лист «История» и адрес скрипта. Участнику
  ничего вставлять не нужно — при первом открытии состав и явка подгружаются сами.

## Как запустить

```bash
cd teambalancer
./start.sh
```

Скрипт напечатает два адреса: локальный и для телефона (по Wi-Fi). Откройте второй на телефоне.

Дальше на телефоне:

- **iPhone:** Safari → «Поделиться» → «На экран “Домой”».
- **Android:** Chrome → меню ⋮ → «Установить приложение».

Офлайн-режим и установка как приложение требуют `https` (или `localhost`).
По локальному адресу `http://192.168.x.x` всё работает, но как обычная веб-страница.
Если нужен полноценный офлайн — положите папку на любой https-хостинг (GitHub Pages, nginx).

## Установка и удаление

- В «Настройках» есть кнопка **«Установить приложение»** — она вызывает штатное окно установки
  браузера (появляется, когда браузер готов ставить; Chrome на iPhone веб-приложения не ставит).
  Под кнопкой всегда написано, как поставить приложение в том браузере, где оно открыто.
- Если приложение уже открыто как установленное, вместо неё показывается **«Удалить приложение»**:
  веб-приложение не может удалить себя само, поэтому диалог даёт точный путь для iPhone, Android и
  компьютера, плюс кнопку «Стереть данные» (состав, настройки, офлайн-кэш).

## Другие браузеры (в том числе Яндекс)

Приложение не привязано к Chrome: это обычный сайт на HTML/CSS/JS без сборки. Различия только
в **установке** — её делает браузер, а не приложение. На экране «Настройки» подсказка подставляется
под тот браузер, где открыта страница:

| Где открыто | Как поставить |
|---|---|
| Chrome, Edge, Opera, Яндекс Браузер на компьютере | меню ⋮ → «Установить приложение» (у Chrome и Edge бывает иконка в адресной строке) |
| Android (Chrome, Яндекс, Firefox) | меню ⋮ → «Установить приложение» / «Добавить на главный экран» |
| iPhone и iPad (любой браузер) | «Поделиться» → «На экран “Домой”»; надёжнее всего в Safari |
| Safari на macOS | «Файл» → «Добавить в Dock» |
| Firefox на компьютере | отдельным окном не ставится — открывать в Chrome / Яндекс Браузере / Edge / Safari |

Что работает в любом из них: состав и явка из Google Таблицы, распределение, история и статистика,
диалоги, офлайн-оболочка (service worker). Признак «уже установлено» считается по
`display-mode: standalone` и `navigator.standalone`, поэтому работает и в не-Chrome.

Про Яндекс Браузер честно: он на движке Chromium, поэтому ведёт себя как Chrome, но **в живом
Яндекс Браузере приложение не проверялось** — на машине разработки его нет. Если в меню не окажется
пункта установки, приложение об этом пишет и предлагает открыть ссылку в Chrome. В старых сборках
Яндекса (как и любого Chromium до 111) не поддерживается CSS `color-mix` — для карточек команд
оставлен запасной фон без него, поэтому вёрстка не поедет.

## Переход в таблицу из приложения

Рядом с каждым адресом (состав и лист явки) есть кнопка **↗** — открывает эту же таблицу в новой
вкладке на редактирование, сохраняя номер листа (`#gid=…`). Менять состав или отметки можно прямо
с телефона, не разыскивая ссылку.

## Google Таблица

1. Лист с шапкой в первой строке. Колонки в любом порядке, распознаются по названиям
   (русские и английские): `Имя`, `Скорость`/PAC, `Удар`/SHO, `Пас`/PAS, `Дриблинг`/DRI,
   `Защита`/DEF, `Физика`/PHY, `Реакция`/REF, `Позиционирование`/POS.
2. Доступ: «Поделиться» → «Все, у кого есть ссылка» → **Читатель**. Иначе Google вернёт страницу вместо CSV.
3. Ссылку вставьте в приложение и нажмите «Загрузить». При загрузке состав **заменяется** данными листа.
   «Вставить CSV» наоборот **дополняет** состав и обновляет совпадающие по имени строки.

**Игроков, добавленных в приложении («+ игрок»), в таблице не будет.** Приложение читает лист,
но состав в него не пишет. Такой игрок живёт только на этом телефоне, помечен в списке меткой
«только здесь» и исчезнет при загрузке состава из листа — приложение предупредит об этом и
перечислит имена. Чтобы игрок был у всех, заведите его в листе состава.

Образец — `players-template.csv`: его можно импортировать в Google Таблицы
(Файл → Импорт) и заменить имена и оценки на свои.

Текущий состав команды с черновыми оценками — `players.csv` (19 игроков, те же колонки,
что в листе). Кнопка «Демо» в приложении загружает **обезличенный** пример на 19 игроков.

Реальные файлы состава (`players.csv`, `players-template.csv`) лежат только локально
и в публичный репозиторий не попадают — они в `.gitignore`.

## Быстрая оценка

Кнопка «Быстрая оценка» в блоке «Игроки» открывает список состава: у каждого игрока два поля —
**в поле** и **в воротах**. Ставите числа (1–10, дробные можно), жмёте «Применить» — скилы
становятся ровными: все 6 полевых равны «в поле», оба вратарских равны «в воротах».

Для баланса этого достаточно: алгоритм сравнивает именно эти две оценки, а не отдельные скилы.
19 игроков — 38 чисел вместо 152. Подробный ввод по 8 полям остаётся в карточке игрока.

## Явка на игру

Приложение читает лист с явкой и распределяет только тех, кто придёт.

**Формат листа — «игроки × даты»:** строки это игроки, колонки это даты игр.

| Имя | 17.11.2026 | 24.11.2026 |
|---|---|---|
| Юра | + | − |
| Гриша | + |  |

- `+` (или `да`, `иду`, `1`) — придёт; `−` (или `нет`, `0`) — не придёт; пусто — без ответа.
  Выпадающий список «Играю / Не играю» тоже понимается.
- Приложение берёт **ближайшую дату, начиная с сегодняшней**, и читает только её колонку:
  после игры оно само переключится на следующую (17.11 → 24.11 → 1.12 …), ничего менять не надо.
  Поэтому лист можно вести на месяцы вперёд. Какая колонка взята — написано в плашке «игра <дата>».
  Если все даты уже прошли, берётся последняя колонка, где есть отметки.
- **Дату можно выбрать вручную.** Под кнопкой «Загрузить явку» появляется список
  «Дата игры для распределения»: `авто — ближайшая` плюс все даты из шапки листа с числом отметок.
  Выбор запоминается, в сводке подписано «дата выбрана вручную». Так можно разложить состав на
  прошедшую игру (для истории) или сразу на дальнюю дату, не дожидаясь её.
- Показывает «придут / не смогут / без ответа» и перечисляет не ответивших.
- Тумблер «Только те, кто придёт» включается сам, если есть хотя бы один плюс; без отметок —
  распределяется весь состав.
- Имена сопоставляются без учёта регистра и точек; незнакомые показываются предупреждением.

Ссылку на лист берите прямо из адресной строки Google Таблиц — вместе с `#gid=` нужного листа.
Доступ: «Все, у кого есть ссылка — читатель».

Лист ответов Google Формы (Отметка времени / Дата игры / Игрок / Приду) тоже поддерживается —
дата выбирается по тому же правилу: ближайшая не прошедшая.

## История игр и статистика

История живёт в **листе `История`** той же Google Таблицы. Одна игра — одна строка.

| ID | Дата | Команд | Итог | Синие | Красные | Белые | Обновлено |
|---|---|---|---|---|---|---|---|
| 2026-11-17 | 17.11.2026 | 3 | Синие–Красные 3:1; Синие–Белые 2:2; Красные–Белые 1:0 | Юра 8.0/6.0; Гриша 7.0/4.0 | Дима 7.5/5.0 | Антон 6.0/4.0 | … |

- `ID` — дата игры: по ней строка обновляется, а не дублируется.
- `Итог` — пары со счётом. Для 3 команд это круговой: А–Б, А–В, Б–В (пустая пара — не играли).
- В ячейке состава: `Имя поле/ворота`, игроки через `;`.

**Запись из приложения.** На экране «Команды» после распределения есть кнопка
**«Сохранить игру»**: открывается список матчей (для 3 команд заготовлен круговой — три пары,
любую можно оставить пустой), затем строка уходит в лист. Счёт можно вписать позже —
кнопкой «Вписать счёт» в истории.

**Матчей за день может быть много.** Игровой день — это серия: поделились на команды и играют
несколько матчей подряд (например, победитель остаётся, проигравший уходит на скамейку, каждая
команда играет не больше двух подряд). Поэтому в диалоге счёта **каждый матч — отдельная строка**:
выбираются две команды и вводится счёт, кнопка **«＋ ещё матч»** добавляет строку, `×` убирает.
Пары могут повторяться сколько угодно раз. Дописать матчи можно и после игры: в «Истории» у каждой
игры есть кнопка **«＋ матч»** — она открывает тот же список с пустой строкой в конце.

Чтобы приложение могло писать, нужен один раз настроенный скрипт (Настройки → «История: как подключить»):

1. В таблице создать лист `История` (пустой — шапку поставит скрипт).
2. **Расширения → Apps Script**, вставить код из настроек.
3. **Развернуть → Новое развёртывание → «Веб-приложение»**: запуск от своего имени, доступ — «все».
   Адрес (кончается на `/exec`) вставить в поле «Адрес веб-приложения» на экране «История».
4. Ссылку на лист `История` (с `#gid=…`) вставить там же — по ней читается история и статистика.

Код лежит рядом: [`apps-script.js`](apps-script.js) — тот же текст, что в «Настройках» приложения
(кнопка «Скопировать код»), поэтому копировать можно оттуда.

Запись идёт POST-запросом (`text/plain`, без CORS-предзапроса), поэтому ответ не читается:
после сохранения приложение через пару секунд перечитывает лист и показывает, что игра на месте.

**Важно про развёртывание.** Развёртывание Apps Script фиксирует версию кода. Если код в редакторе
обновили, а развёртывание не пересоздали, работает **прежняя** версия. Признак, что работает
старый скрипт: повторное сохранение той же даты добавляет в лист вторую строку, а «Удалить» в
приложении оставляет строку на месте. Тогда: «Развернуть» → «Управление развёртываниями» →
карандаш → версия «Новая» → «Развернуть».

**Про колонку `ID`.** Google Таблицы охотно превращают `2026-11-17` в дату, и тогда сравнение со
строкой не совпадает — сохранение дописывает дубль, а удаление ничего не находит. Скрипт держит
колонку `ID` в текстовом формате и сравнивает значения через нормализацию даты, поэтому старые
строки с датой тоже находятся. Если у даты в листе уже несколько строк, при сохранении остаётся
одна — свежая, лишние удаляются: так дубли чистятся сами.

Повторное сохранение той же даты обновляет строку по `ID`. Если в листе всё же оказались две строки
с одним `ID` (например, сохранено прежней версией скрипта), приложение показывает одну карточку —
берёт нижнюю (свежую).

**Без скрипта** приложение всё равно сохраняет игру — на телефоне, с пометкой «не в таблице»
и кнопкой «Отправить в таблицу». Так можно начать пользоваться и настроить запись позже.
Удаление игры убирает и строку листа; если скрипт этого не умеет, приложение честно скажет,
что строку надо удалить вручную.

### Что показывает статистика

- **Посещаемость и очки** — по каждому игроку: сколько игровых дней был в составе, сколько матчей
  провёл в них (в серии «победитель остаётся» их бывает и три, и четыре за день), сколько
  выиграл/свёл/проиграл и сколько набрал очков (3 за победу, 1 за ничью).
- **Сыгранность** — пары игроков, которые чаще всех оказывались в одной команде. Считается только
  по сохранённым играм, поэтому в одной игре видно лишь тех, кто в ней был; ниже подписано, сколько
  пар всего.
- **Баланс и результат** — в скольких играх со счётом команда с самой большой суммой скилов
  набрала больше всех очков. Высокая доля значит, что распределение по скилам предсказывает
  результат; низкая — что решает что-то ещё (вратарь, сыгранность, случай).

Если в листе оказалось **несколько строк на одну дату** (так бывает со старым скриптом), на экране
«История» появляется карточка «В листе дубли» с датой и числом строк: приложение показывает одну
свежую строку, и статистика считается по ней. После обновления скрипта достаточно сохранить игру
за эту дату ещё раз — лишние строки удалятся сами.

## Как считается распределение

1. Каждому игроку считаются две оценки — «в поле» и «в воротах».
2. Стартовое разбиение — жадный проход от сильных к слабым: каждый попадает в команду
   с наименьшей текущей суммой.
3. Затем локальная оптимизация: обмены игроками между командами, пока оценка улучшается.
4. 240 рестартов со случайным отклонением — берётся лучший вариант.
5. Для **2 команд** при составе до 19 человек работает точный перебор: результат гарантированно оптимален.

Критерий: `1000 × разница сумм в поле + 600 × разница сумм в рамке + штраф за корзины`
(вратарская часть и корзины отключаются галочками). Размеры команд отличаются максимум на одного игрока.

**Корзины (ярусы).** Игроки сортируются по силе и нарезаются на ярусы с шагом «число команд»
(19 игроков, 3 команды → ярусы по 3). Каждая команда получает по одному игроку из яруса.
Верхняя корзина ограничена жёстко: **не больше одного топ-игрока в команде** (в результате
он отмечен ★), остальные ярусы — мягко, как приоритет при равных суммах.

Почему так, а не «просто сумма»: суммы не видят разброса. `7+7+7+7+7` и `10+6+6+6+7` дают
одинаковые 35, но во второй команде «звезда + балласт». Корзины это убирают: сильные
расходятся по разным командам. При этом суммы остаются главным критерием — они понятны игрокам
и при равных составах честны.

Ещё два известных ограничения суммы: при разном размере команд равные суммы означают
разную силу «на игрока» (в приложении это поясняется под результатом), и она не учитывает
сыгранность. В любительском футболе честность даёт не идеальное одно разбиение, а ротация
составов между играми.

Если игроков нечётное число, команды получаются разного размера (например 8 и 7).
Тогда разница сумм неизбежна: в меньшую команду попадают игроки посильнее — это
компенсация за меньшее число. Приложение честно пишет об этом под результатом,
а для двух команд ставит вердикт «оптимум» (лучше при таком составе не сделать).

Обновление:

```bash
cd ~/Documents/OS_help/teambalancer
git add -A && git commit -m "что изменилось" && git push
```

Pages пересобирается сам за минуту, адрес не меняется. Приложение обновляется у всех
при следующем открытии: service worker тянет файлы из сети и кэширует их только как запасной
вариант для офлайна. Проверить версию можно в «Настройках» — внизу написано «Версия N».

один раз вставить ссылку на Google Таблицу с составом → «Загрузить». Дальше у каждого
своя копия настроек и одинаковый состав из таблицы.
