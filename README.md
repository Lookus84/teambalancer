# Баланс команд

Мобильное веб-приложение (PWA) для распределения игроков в футбол на 2 или 3 команды
с примерно равной суммой скилов. Без сборки, без зависимостей, без бэкенда.

## Главное про модель

Вратарём может встать **любой**, и в поле игроки тоже меняются позициями.
Поэтому:

- у каждого игрока заполняются **все 8 скилов** — 6 полевых и 2 вратарских;
- колонка «Позиция» не нужна и не используется;
- у игрока две оценки: **«в поле»** и **«в воротах»**;
- в результате для каждой команды подписан сильнейший вратарь — кто может встать в рамку.

## Скилы (шкала 1–10, можно половинки)

**Поле:** Скорость, Удар, Пас, Дриблинг, Защита, Физика.
**Ворота:** Реакция, Позиционирование.

«В поле» и «в воротах» — простое среднее по своей группе. Пустые ячейки подставляются
средними по составу, так что недозаполненная таблица не ломает баланс.
Если в таблице числа из FIFA (0–99), они автоматически делятся на 10.

## Что умеет

- Состав из **Google Таблицы** по ссылке, вставкой CSV или вручную.
- Делит на **2 или 3 команды**: выравнивает сумму полевых оценок, а при включённой
  галочке — и сумму вратарских.
- Показывает суммы, средние по команде, вратарскую сумму и вратаря каждой команды.
- Кнопка «Ещё вариант» пересобирает состав, «Поделиться» отдаёт текст в мессенджер.

## Как запустить

```bash
cd teambalancer
./start.sh
```

Скрипт напечатает два адреса: локальный и для телефона (по Wi-Fi). Откройте второй на телефоне.

Дальше на телефоне:

- **iPhone:** Safari → «Поделиться» → «На экран “Домой”».
- **Android:** Chrome → меню ⋮ → «Установить приложение».

Офлайн-режим и установка как приложение требуют `https` (или `localhost`).
По локальному адресу `http://192.168.x.x` всё работает, но как обычная веб-страница.
Если нужен полноценный офлайн — положите папку на любой https-хостинг (GitHub Pages, nginx).

## Google Таблица

1. Лист с шапкой в первой строке. Колонки в любом порядке, распознаются по названиям
   (русские и английские): `Имя`, `Скорость`/PAC, `Удар`/SHO, `Пас`/PAS, `Дриблинг`/DRI,
   `Защита`/DEF, `Физика`/PHY, `Реакция`/REF, `Позиционирование`/POS.
2. Доступ: «Поделиться» → «Все, у кого есть ссылка» → **Читатель**. Иначе Google вернёт страницу вместо CSV.
3. Ссылку вставьте в приложение и нажмите «Загрузить». При загрузке состав **заменяется** данными листа.
   «Вставить CSV» наоборот **дополняет** состав и обновляет совпадающие по имени строки.

Образец — `players-template.csv`: его можно импортировать в Google Таблицы
(Файл → Импорт) и заменить имена и оценки на свои.

Текущий состав команды с черновыми оценками — `players.csv` (19 игроков, те же колонки,
что в листе). Кнопка «Демо» в приложении загружает **обезличенный** пример на 19 игроков.

Реальные файлы состава (`players.csv`, `players-template.csv`) лежат только локально
и в публичный репозиторий не попадают — они в `.gitignore`.

## Быстрая оценка

Кнопка «Быстрая оценка» в блоке «Игроки» открывает список состава: у каждого игрока два поля —
**в поле** и **в воротах**. Ставите числа (1–10, дробные можно), жмёте «Применить» — скилы
становятся ровными: все 6 полевых равны «в поле», оба вратарских равны «в воротах».

Для баланса этого достаточно: алгоритм сравнивает именно эти две оценки, а не отдельные скилы.
19 игроков — 38 чисел вместо 152. Подробный ввод по 8 полям остаётся в карточке игрока.

## Явка на игру

Приложение читает лист с явкой и распределяет только тех, кто придёт.

**Формат листа — «игроки × даты»:** строки это игроки, колонки это даты игр.

| Имя | 17.11.2026 | 24.11.2026 |
|---|---|---|
| Юра | + | − |
| Гриша | + |  |

- `+` (или `да`, `иду`, `1`) — придёт; `−` (или `нет`, `0`) — не придёт; пусто — без ответа.
- Приложение берёт **ближайшую дату, начиная с сегодняшней**, поэтому лист можно вести на месяцы вперёд.
- Показывает «придут / не смогут / без ответа» и перечисляет не ответивших.
- Тумблер «Только те, кто придёт» включается сам, если есть хотя бы один плюс; без отметок —
  распределяется весь состав.
- Имена сопоставляются без учёта регистра и точек; незнакомые показываются предупреждением.

Ссылку на лист берите прямо из адресной строки Google Таблиц — вместе с `#gid=` нужного листа.
Доступ: «Все, у кого есть ссылка — читатель».

Лист ответов Google Формы (Отметка времени / Дата игры / Игрок / Приду) тоже поддерживается —
если он подхватится, приложение работает по последней дате игры и последнему ответу игрока.

## Как считается распределение

1. Каждому игроку считаются две оценки — «в поле» и «в воротах».
2. Стартовое разбиение — жадный проход от сильных к слабым: каждый попадает в команду
   с наименьшей текущей суммой.
3. Затем локальная оптимизация: обмены игроками между командами, пока оценка улучшается.
4. 240 рестартов со случайным отклонением — берётся лучший вариант.
5. Для **2 команд** при составе до 19 человек работает точный перебор: результат гарантированно оптимален.

Критерий: `1000 × разница сумм в поле + 600 × разница сумм в рамке + штраф за корзины`
(вратарская часть и корзины отключаются галочками). Размеры команд отличаются максимум на одного игрока.

**Корзины (ярусы).** Игроки сортируются по силе и нарезаются на ярусы с шагом «число команд»
(19 игроков, 3 команды → ярусы по 3). Каждая команда получает по одному игроку из яруса.
Верхняя корзина ограничена жёстко: **не больше одного топ-игрока в команде** (в результате
он отмечен ★), остальные ярусы — мягко, как приоритет при равных суммах.

Почему так, а не «просто сумма»: суммы не видят разброса. `7+7+7+7+7` и `10+6+6+6+7` дают
одинаковые 35, но во второй команде «звезда + балласт». Корзины это убирают: сильные
расходятся по разным командам. При этом суммы остаются главным критерием — они понятны игрокам
и при равных составах честны.

Ещё два известных ограничения суммы: при разном размере команд равные суммы означают
разную силу «на игрока» (в приложении это поясняется под результатом), и она не учитывает
сыгранность. В любительском футболе честность даёт не идеальное одно разбиение, а ротация
составов между играми.

Если игроков нечётное число, команды получаются разного размера (например 8 и 7).
Тогда разница сумм неизбежна: в меньшую команду попадают игроки посильнее — это
компенсация за меньшее число. Приложение честно пишет об этом под результатом,
а для двух команд ставит вердикт «оптимум» (лучше при таком составе не сделать).

## Проверено

- Логика (node): парсинг CSV с русской шапкой, без шапки, с `;`, боевой состав из Google Таблицы, таблица со старой колонкой
  «Позиция» тоже читается (колонка игнорируется); оценки «поле/ворота»; подстановка пустых
  скилов; 3 команды и 2 команды; оптимальность для 2 команд сверена с независимым перебором;
  вырожденные случаи.
- Интерфейс (headless Chrome): 320/360/390/430 px без горизонтальной прокрутки, демо-состав,
  диалог с 8 полями без выбора позиции, 2 и 3 команды с подписанным вратарём, пояснение
  про разный размер команд, сохранение состава после перезагрузки, отсутствие ошибок в консоли.
- Явка: разбор форматов дат (`14.11.2026`, `2026-11-14`, `14 ноября`), «Приду / Не приду /
  Нет, не смогу», последний ответ игрока важнее предыдущего, выбор последней даты игры.
  Сквозной сценарий в браузере: 19 в составе → 12 придут / 4 не смогут / 3 без ответа →
  распределение ровно 12 (4/4/4), не пришедшие исключены, сброс явки возвращает полный состав.
- Боевой состав (`players.csv`, 19 игроков): 3 команды — поле 38.7 / 38.5 / 38.5, рамка 31.6 / 31.0 / 31.0;
  2 команды — 57.9 / 57.8 при разнице в рамке 0.0 (точный перебор, 52 мс).
